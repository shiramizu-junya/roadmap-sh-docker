# 01. 用語の逆引き

「自分の言葉」の列は読者が埋めます。読み返して使える形で書いてください。

| 用語 | 正式名称 | 🧒 かみくだくと | 定義 | 初出 | 自分の言葉 |
| --- | --- | --- | --- | --- | --- |
| コンテナ | container | 箱を開けて生活を始めた部屋 | イメージから起動した、隔離されたプロセス | P0-1 | |
| イメージ | container image | 封をした段ボール | アプリと実行に要るものをまとめた、コンテナの元 | P0-1 | |
| 共有ライブラリ | shared library | みんなの道具箱 | 複数のプログラムが共通で使う部品 | P0-1 | |
| カーネル | kernel | パソコンの管理人 | アプリの要求を受けて機械を動かす、OS の中心部分 | P0-2 | |
| VM | virtual machine | ソフトだけのパソコン | 機械を仮想的に作り、その上で別の OS を動かす仕組み | P0-2 | |
| ベアメタル | bare metal | 本物の機械 | 仮想化をしない物理マシン | P0-2 | |
| ホスト | host | コンテナが住む建物 | 本教材では、コンテナのすぐ外側の Linux VM | P0-2 | |
| ゲスト | guest | 建物に入る側 | ホストの上で動く側 | P0-2 | |
| デーモン | daemon | 頼まれるのを待つ裏方 | 裏で動き続けるプログラム。Docker では `dockerd` | P0-3 | |
| レジストリ | container registry | 配送センター | イメージを保管して配るサービス | P0-3 | |
| OCI | Open Container Initiative | 段ボールの規格の団体 | イメージと実行方法の標準を定める団体 | P0-3 | |
| containerd | containerd | コンテナの管理係 | コンテナの一生を管理するランタイム | P0-3 | |
| runc | runc | コンテナの組み立て係 | OCI の仕様に沿ってコンテナを作る低レベルランタイム | P0-3 | |
| ポート | port | 建物の部屋番号 | 通信の届け先のプログラムを分ける番号 | P1-1 | |
| タグ | tag | 箱に貼るラベル | イメージの版や種類を示す名前 | P1-1 | |
| Docker Hub | Docker Hub | 大きな配送センター | Docker 社が運営する公開レジストリ | P1-2 | |
| 標準出力 | standard output | 画面に向けて出す文字 | プログラムの通常の出力先。`docker logs` で読める | P1-3 | |
| PID | process ID | プロセスの出席番号 | プロセスに付く番号 | P1-4 | |
| UID | user ID | ユーザの番号 | Linux がユーザを識別する番号 | P1-4 | |
| namespace | Linux namespace | 部屋の壁 | プロセスごとに見える範囲を分けるカーネルの機能 | P1-4 | |
| cgroup | control group | 部屋ごとの電気の上限 | CPU やメモリの使用量を制限するカーネルの機能 | P1-4 | |
| OOM Kill | Out Of Memory Kill | メモリ切れの強制終了 | メモリ不足のときにカーネルがプロセスを終了させること | P1-4 | |
| 書き込み層 | container layer | 一番上の透明フィルム | コンテナごとの書き込み可能な層 | P1-5 | |
| overlay | OverlayFS | 透明フィルムの重なり | 複数のディレクトリを重ねて1つに見せるファイルシステム | P1-5 | |
| Dockerfile | Dockerfile | 荷造りの手順書 | イメージの作り方を上から順に書いたファイル | P2-1 | |
| Debian | Debian | Linux の配布形態の1つ | `python:3.13-slim` の土台になっている Linux ディストリビューション | P2-1 | |
| 作業ディレクトリ | working directory | 今いる場所 | コマンドの相対パスの起点になる場所。Dockerfile では `WORKDIR` で決める | P2-2 | |
| レイヤ | image layer | 荷物を層ごとに積んだもの | Dockerfile の命令が作る、読み取り専用のファイルの差分 | P2-3 | |
| ロックファイル | lockfile | 入れた版の明細書 | 依存の版を固定して記録するファイル。本教材では `uv.lock` | P2-3 | |
| ビルドコンテキスト | build context | 箱に入れる材料の置き場 | `docker build` に渡す、材料のファイル一式 | P2-4 | |
| ビルドキャッシュ | build cache | 前回の荷造りの記録 | 同じ結果になる命令で、前の層を使い回す仕組み | P2-4 | |
| BuildKit | BuildKit | ビルドの実行係 | Docker の中でイメージをビルドする部品 | P2-4 | |
| PID 1 | PID 1 | 箱の中の最初のプロセス | コンテナの寿命を決め、`docker stop` のシグナルを受けるプロセス | P2-5 | |
| シグナル | signal | カーネルからの短い合図 | プロセスに渡す通知。SIGTERM は終了のお願い、SIGKILL は強制終了 | P2-5 | |
| volume | volume | 建物の外の貸し倉庫 | Docker が管理する、コンテナと別に残る保存場所 | P3-1 | |
| マウント | mount | 部屋の扉を倉庫につなぐ工事 | 保存場所を、ディレクトリツリーの1か所につなぐこと | P3-1 | |
| bind mount | bind mount | 扉を手元のフォルダに直結する工事 | ホストのディレクトリを、コンテナの中へ直接つなぐこと | P3-2 | |
| UID / GID | user ID / group ID | ユーザとグループの番号 | Linux がファイルの持ち主を比べるときの番号 | P3-2 | |
| パーミッション | permission | 誰が触ってよいかの決まり | 持ち主・グループ・その他ごとの、読む・書く・実行の許可 | P3-2 | |
| ネットワーク | Docker network | 建物の中の内線 | コンテナ同士をつなぐ仮想の配線。自作のものは名前で相手を探せる | P3-3 | |
| bridge | bridge driver | 内線の配線方式 | ホストの中に仮想の配線を作る、既定のネットワークドライバ | P3-3 | |
| IP アドレス | IP address | 内線番号 | ネットワーク上の相手を指す番号 | P3-3 | |
| DNS | Domain Name System | 電話帳 | 名前から IP アドレスを調べる仕組み | P3-3 | |
| 環境変数 | environment variable | プロセスに貼る付箋 | プロセスが起動したあとに読める `名前=値` の設定 | P3-4 | |
| パッケージ | package | OS に足す部品の箱 | `apt-get` などで入れる、ソフトの部品 | P3-4 | |
| マイグレーション | migration | 表の設計図の反映手順 | モデルの定義を DB の表に反映する手順書 | P3-4 | |
| fixture | fixture | 最初に入れておくデータ | `loaddata` で DB に入れる、データのファイル | P3-4 | |
